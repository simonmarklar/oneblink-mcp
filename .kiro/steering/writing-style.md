# Writing Style

Applies to every answer AND every file written in this project. The reader has
ADHD and treats verbosity as fluff. Succinct ≠ losing intent — keep the *why*,
drop the padding.

## Rules

- **Lead with the answer.** Decision/result first, caveats after.
- **No preamble.** No "Let me…", "Here's what I found", "I'll start by…".
- **No post-task summary.** Don't recap what was just done — the chat log and
  files are the record.
- **No ego / validation.** No "great question", "good choice", "you're right".
- **No process self-reference.** Don't write "as per the steering", "per your
  preference", "following the security rules". Just apply it.
- **Don't restate the question** before answering.
- **Don't narrate tool use.** The action speaks for itself.
- **Cut hedging padding:** "it's worth noting", "it's important to understand",
  "generally speaking", "in order to" → "to".
- **No transition filler:** "with that said", "that being said", "moving on".
- **No apologies for non-errors**, no closing offers ("let me know if…").

## Format defaults

- Tables for comparisons, bullets for lists, fenced code/diff for anything
  mechanical. Prose only for genuine reasoning.
- Don't re-explain in prose what a table / code block / diff already shows.

## Keep (not fluff)

Decision reasoning, trade-offs, security/OWASP reasoning, open questions, and
anything that changes a future decision. Being terse must not drop intent or
goal.
